# DT Daily AI Briefing System

Pulls AI news from RSS feeds and web search, analyzes each item using the Anthropic API, and delivers a formatted brief to your Gmail at 7am daily.

---

## Step 1 — Clone and create a virtual environment

```bash
git clone <your-repo-url>
cd daily-briefing
python3 -m venv venv
source venv/bin/activate        # macOS / Linux
# venv\Scripts\activate         # Windows
```

---

## Step 2 — Install dependencies

```bash
pip install -r requirements.txt
```

---

## Step 3 — Add your Anthropic API key

```bash
cp .env.example .env
```

Open `.env` and set your key:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Never commit `.env` to version control. It is listed in `.gitignore`.

---

## Step 4 — Set up Gmail API credentials

1. Go to [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project (e.g., `DT-Briefing`).
3. In the left menu, go to **APIs & Services > Library**. Search for **Gmail API** and enable it.
4. Go to **APIs & Services > Credentials**.
5. Click **Create Credentials > OAuth client ID**.
6. Set Application type to **Desktop app**. Name it anything.
7. Click **Download JSON**. Rename the file to `credentials.json` and place it in the `daily-briefing/` project root.
8. Go to **APIs & Services > OAuth consent screen**. Add your Gmail address (`drdee20200@gmail.com`) as a **Test user**.

`credentials.json` is listed in `.gitignore` and will never be committed.

---

## Step 5 — Authorize Gmail (one time only)

```bash
python auth.py
```

A browser window will open. Sign in with your Google account and grant the requested permission (send email only). This generates `token.json` in the project root. You will not need to do this again unless the token is deleted or expires without a refresh.

`token.json` is listed in `.gitignore` and will never be committed.

---

## Step 6 — Add your Gmail address to config.py

Open `config.py` and set:

```python
RECIPIENT_EMAIL = "drdee20200@gmail.com"
```

---

## Step 7 — Test manually

```bash
python briefing.py
```

Check your inbox and review `briefing.log` for any errors.

---

## Step 8 — Set up the daily cron job (7am)

Open your crontab:

```bash
crontab -e
```

Add this line, replacing the paths with your actual paths:

```
0 7 * * * /path/to/daily-briefing/venv/bin/python /path/to/daily-briefing/briefing.py >> /path/to/daily-briefing/briefing.log 2>&1
```

To find your paths:

```bash
which python          # inside the venv after source venv/bin/activate
pwd                   # from inside the daily-briefing directory
```

## File reference

| File | Purpose |
|---|---|
| `briefing.py` | Main script. Run this daily. |
| `auth.py` | One-time Gmail OAuth2 setup. |
| `config.py` | All user-editable settings: feeds, queries, model, recipient. |
| `requirements.txt` | Python dependencies. |
| `.env` | Your secret API key. Never commit. |
| `credentials.json` | Gmail OAuth2 client secrets from Google. Never commit. |
| `token.json` | Gmail access token generated by auth.py. Never commit. |
| `briefing.log` | Running log of all runs, errors, and delivery status. |

---

## Customization

All tunable settings live in `config.py`:

- **Add or remove RSS feeds** — edit `RSS_FEEDS_PRIMARY` or `RSS_FEEDS_SECONDARY`.
- **Change search queries** — edit `SEARCH_QUERIES`.
- **Change the lookback window** — edit `LOOKBACK_HOURS` (default: 24).
- **Change the recipient** — edit `RECIPIENT_EMAIL`.
- **Change the Anthropic model** — edit `ANTHROPIC_MODEL`.

---

## Error handling

- If an RSS feed fails, the run continues and the error is logged.
- If a web search returns no results, the run continues.
- If an Anthropic API call fails on one item, that item is skipped and logged.
- If Gmail send fails, the system retries once after 60 seconds. Failure is logged.
- If no items pass the relevance filter, the email is still sent with a "Nothing relevant flagged today" message so you know the system ran.

All errors are timestamped in `briefing.log`.
